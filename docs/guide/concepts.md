# Core Concepts

This guide explains the core concepts used by Eutaxis to assemble agent prompts
and instruction files.

## Instruction Sources

An **instruction source** is a Markdown file that contains reusable guidance.
Sources usually live in project documentation directories, for example:

```text
docs/instructions/
  global-defaults.md
  repository-structure.md
  python-environment.md
  writing-style.md
```

Sources should be small enough to review independently. Broad instruction files
can still be used by selecting named sections from them.

## Source Selection

A source entry controls which part of a Markdown file appears in the generated
output. Eutaxis can:

- include the full file;
- include only named heading sections;
- exclude named heading sections;
- strip YAML frontmatter;
- shift heading levels with `heading_offset`.

Section selection includes the selected heading and nested subsections until the
next heading at the same or higher level.

## Common Sources

**Common sources** are included in every enabled output declared by the config.
They are useful for rules that should reach every agent, such as repository
layout, environment policy, verification rules, or shared writing constraints.

```yaml
common_sources:
  - docs/instructions/repository-structure.md
  - docs/instructions/python-environment.md
```

## Agent Outputs

An **agent output** is one generated instruction file. Each output has:

- a `name`, used by CLI filters and status messages;
- a `target`, which defines the output path and optional header/footer;
- optional output-specific `sources`;
- an `enabled` flag.

The same config can generate several instruction files:

```yaml
agents:
  - name: codex
    target: AGENTS.md

  - name: claude
    target: .claude/CLAUDE.md

  - name: copilot
    target: .github/copilot-instructions.md
```

## Project-Level Generation

For a project-level instruction set, place `agent-instructions.yaml` at the
repository root. Relative source and target paths resolve against the config
file's parent directory unless `root` is set.

This pattern supports generated files such as:

- `AGENTS.md`
- `.claude/CLAUDE.md`
- `.github/copilot-instructions.md`

## Global Generation

Global instruction files can be generated by setting `root` to the directory
that owns the reusable source modules and using an absolute target path:

```yaml
root: /Users/eresther/Documents/work/projects/instruction-modules

agents:
  - name: global-codex
    target:
      path: /Users/eresther/.codex/AGENTS.md
```

This lets global defaults and project-specific instruction files use the same
assembly mechanism.

## Generated Files

Generated instruction files should not be edited by hand. Edit the source
modules or config, then regenerate the outputs:

```sh
eutaxis generate -c agent-instructions.yaml
```

Use `eutaxis check` in local validation or CI to detect stale outputs.

## Compatibility Layer

The public instruction assembly API lives under `eutaxis.instructions`. The
older `eutaxis.generate` module remains available as a compatibility facade for
scripts and tests that imported the first implementation.

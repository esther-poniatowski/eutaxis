# Structured declaration system plan

This plan implements the accepted structured-source decisions and assigns only work owned by Eutaxis. A consuming repository owns the cross-project assignment between its sources, Eutaxis, and other providers; that assignment is not duplicated here.

## Current state

Prompts still originate in free-form Markdown. By contrast, the first schema now governs a canonical `.yaml` corpus. The source loader rejects malformed sources. The source loader returns immutable models and conjoins inherited applicability predicates.

Independent adversarial reviews approved the complete normative contract on three results. First, the valid packaged corpus returns `satisfied`. Second, its unresolved-reference fixture returns a located `violated` diagnostic. Third, the packaged procedure satisfies three static facts. The procedure binds every operation input. The procedure routes every outcome. The procedure declares no effects.

`eutaxis/load-declaration-registry` now runs through a code-owned callable. Before calling it, Eutaxis validates an immutable input. After it returns, Eutaxis validates either immutable outputs or a declared failure.

A self-contained cumulative fixture plans and mechanically assembles a certified compilation unit. The public resolver now supplies the same boundary from validated sources and one typed context. The fixture covers three resolution results:

- a prerequisite added from the dependency closure
- a policy substitute used in place of the authored prerequisite
- a retained rule-set member not named directly in the manifest

The planner orders each prerequisite before its dependant. Resolver-assigned anchors order unrelated records. The planner rejects malformed supplied graphs, anchors, and rule projections.

The assembler joins an exact set of fixture-projected Markdown blocks into canonical bytes. A second manifest uses the same target for personal and project scopes. The resulting artifacts remain distinct. Every manifest now declares its mechanism without deriving it from the target. The two unimplemented mechanisms are separate-directory and single-slot. The cumulative planner rejects manifests that declare either one.

The static catalog now preserves lookup fields and portable provenance without testing context predicates. The loader validates the schema and cross-row contracts before it builds an immutable view of a persisted index. Both catalog forms apply the same exact static predicates. In both forms, matching rows follow canonical order.

The resolver tests each context predicate, applies conflict policies in simultaneous canonical batches, and issues one certified unit with its explanation trace. The unit contains final-effective rules and procedures, rewritten dependency edges, stable manifest anchors, and final rule-local norm and criterion projections.

The resolver contract now distinguishes selectable containers from records admitted to the output. The same contract fixes five further decisions:

- how the resolver chooses norms and criteria
- how each false or unknown predicate affects its object
- how a policy redirects one dependency
- which objects a successful call returns
- which evidence a failed call may retain

The resolution corpus exercises the public resolver and the composer boundary. Its scenarios cover the completed resolution work listed below.

The attention planner now enumerates enforcement from the registry retained by
that certified result. The live catalog consumes the same canonical enumerator
independently. The planner expands operation preconditions per procedure action
and retains one canonical sequence of every effective completion requirement,
including evaluator-less predicates. Separate deliberative, assisted, and
mechanical packets project from that sequence. Runnable entries retain validated
immutable inputs and their exact runner authorities. Mechanical planning also
requires current known-failure assurance. The resolution trace remains separate
from completion evidence.

When evaluator-less preconditions are present, the procedure observer evaluates
all of them against one coherent provider snapshot. The resulting aggregate does
not authorize the executor to enter the procedure. Evaluator-backed procedure
preconditions are now correlated with the exact run through detached canonical
parameters, predicates, invocation inputs, and schemas. This correlation runs no
evaluator and grants no clearance. The pre-action evidence session now validates
or executes the three enforcement classes in one transaction. That transaction
consumes the evaluator-less observation aggregate, pairs each
assisted execution with a validated residual judgment, retains all evidence for
completion, and derives clearance from the combined precondition results without
executing the same evaluator again. It is a single-use session that enters a
non-reentrant `running` state before any evaluator or callback, executes
detectors before requesting residual judgments, and becomes terminal after
execution starts, including when a later authority check fails. Detector and
checker runner or result failures map to blocked evidence only after authority
is revalidated and do not prevent later canonical preconditions from running.
The completed aggregate retains one typed record per canonical procedure
precondition, with the trace, frozen human evidence, issued detector execution
and residual judgment, validated checker result, or blocking diagnostic owned
by its enforcement class. Separate exact key sets govern manual submissions and
residual providers. One atomic run-scoped claim prevents a second evaluation
plan from claiming the same live run; the weak claim does not retain an
otherwise unreachable run graph. A separate per-session execution claim rejects
concurrent and reentrant calls. One publication snapshot couples terminal state
with issued evidence. The correlation plan retains every detached evaluator
input produced during planning.
The `ProcedureExecutionSession` now owns evaluator-less, manual, assisted, and
mechanical later lifecycle evidence. Its action boundaries combine invariants
with the selected operation preconditions before invocation; its terminal
boundaries combine invariants with only the reached postcondition. Manual
providers receive one privately issued request per realized occurrence.
Assisted providers supply the retained detector input, then judge the residual
question against the exact issued detector execution. Mechanical providers
supply the retained checker input, while a detached checker registry supplies
the only admitted result. Complete, all-satisfied boundary evidence authorizes
an action or terminal acceptance. Detector and checker runner or result failures
produce blocked records only after their authority checks; invalid or replayed
evidence aborts evidence collection.

The exact-once weak run claim, detached factory-time authority, and privately
issued transcript preserve the authorized operation path across hostile
callbacks and interruptions. Execution-time provider authority retains exact
source keys, binding carriers, and callable identities without treating mutable
callable state as contract state. Each terminal transcript separates graph
disposition from adjudication, retains partial failure evidence, and distinguishes
path-inapplicable obligations from abort-unchecked obligations. Mechanical
assurance uses an external issuance record that cannot be rewritten through the
assurance carrier. Each realized mechanical occurrence revalidates structural
authority and fixture digests around its input provider and checker call, without
rerunning known-failure fixtures or retained entry evidence. An unreachable
mechanical postcondition performs no freshness read.
Resolution, requirement, and attention-plan authorities now retain external
identity-indexed weak issuance snapshots. The snapshots cover the complete
resolved unit and trace, canonical requirement projections, packet invocations,
runner registries, fixture carriers, and known-failure assurance. Embedded-state
rewriting and equal-value carrier replacement cannot self-attest a mutation.
Stateful runner internals and current fixture-file bytes remain outside this
structural authority; their respective execution boundaries own those checks.
Procedure preflight now retains one canonical detached lifecycle-evaluation
union for every evaluator-backed invariant, postcondition, and expanded
operation precondition. Each variant binds its exact live source identities to
detached evaluator, invocation, and schema carriers. The run also retains the
detector- and checker-registry origins, including runner identities and frozen
contracts; the execution factory uses those authorities to detach the executable
registries.

The rule-evidence session now evaluates only effective rule criteria, in the
canonical completion-requirement order. It accepts exact manual submissions and
residual providers once, executes detector and checker entries through their
retained authorities, and issues one typed record per criterion. External
identity-bound state protects the session requirements, captured inputs,
lifecycle transitions, requests, executions, and final aggregate. A blocked
runner or result remains evidence and does not stop later criteria; every
authority defect or other post-start failure is terminal. The checker and
detector boundaries reject malformed or equality-spoofing result correlation
fields before they create canonical evidence. Completion reconciliation can now
consume authenticated rule evidence without invoking an evaluator.

The completion ledger now reconciles the canonical requirement sequence with
optional authenticated rule evidence and one sparse, once-snapshotted procedure
outcome mapping. Terminal transcripts contribute retained historical entry and
lifecycle evidence; complete uncleared pre-action aggregates contribute their
entry evidence and leave later requirements unchecked. The ledger derives every
record without evaluator callbacks, preserves every repeated occurrence, and
requires successful graph and adjudication outcomes for every effective
procedure. External issuance snapshots reject mapping re-entry, live-origin
substitution, callback-time state forgery, and later ledger mutation.

The migration-baseline boundary now loads a closed version 1 YAML source,
retains its exact path and byte digest, and issues an explicit ordered selection
from an authenticated registry. A selected baseline can account only for one
exact violated or unchecked rule-criterion record under the resolved manifest
owner, before its canonical UTC expiry. Its digest binds the complete rule
obligation and canonical manual, assisted, mechanical, or absent evidence.
Blocked rule findings, procedure predicates, operation preconditions, and
unsuccessful procedure outcomes remain unwaivable. Resolver, selection,
reconciliation, clock, and ledger authority checks reject callback mutation,
equality-spoofed scalars, path substitution, ambiguous matches, and later
carrier mutation.

## Decision log and open prerequisites

- YAML is canonical; tagged Markdown is only an evidence-triggered fallback.
- Procedures are a declaration kind, separate from the three rule axes.
- Semantic resolution, deterministic artifact composition, and host scope precedence are separate layers.
- External declaration identity and offline acquisition now follow the [accepted namespace and acquisition contract](../adr/external-declaration-identity-and-acquisition.md).
- The external pilot remains blocked until Eutaxis:
  - issues the public acquisition result;
  - writes the persisted catalog with `index-revision: 2`;
  - generates and validates canonical locks through the general command;
  - proves semantic comparison and rollback through general commands; and
  - emits the selected query packet and consumer artifacts.
- SQLite remains conditional on measured JSON-index performance.

The packaged source follows these steps:

1. The module retains the running package directory on a supported descriptor platform.
2. The public acquisition callable keeps the retained directory descriptor private.
3. A detached, validated acquisition lock supplies the code-owned paths and their declaration order.
4. The retained directory opens both resource roots without following symbolic links.
5. The source reads every named carrier and compares its digest with the lock.
6. The source parses only the retained bytes and confirms the facet identifier and owner.
7. The source reopens every logical path. The source compares the directory device and inode values, file metadata, and bytes.
8. The source issues immutable JSON values and exact verified evidence without accepting a caller-supplied root or registry.

callable fails before it opens a resource.
